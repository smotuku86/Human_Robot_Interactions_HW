The easiest way is probably for users to talk to the robot and have it
 move to goals and perform the requested actions. Another option would
 be to allow users to click in the environment to give the robot waypoints 
 and have it determine whether it should grasp or release objects based on 
 its location (for example, near a block → grasp; holding a block over a cabinet → release).

I decided to implement a text-based prompt where the user can ask the robot to perform a step. The
 robot will assist until it believes that step is completed, and it will not provide further 
 assistance until it receives the next request.

I will track a score that increases when cubes are placed in the boxes. I will also increment the

Results Analysis:

We conducted a t-test comparing the assisted user time and score to the unassisted version.

Our hypotheses were:

    Assisted scores would be higher than unassisted scores.
    Assisted completion time would be lower than unassisted completion time.

Both hypotheses were incorrect.

The p-value for the score t-test was 0.9629, which indicates that the 
 unassisted scores were statistically better than the assisted scores. 
 This makes sense because the unassisted trials had higher scores overall.

The time hypothesis resulted in a p-value of 0.2544, suggesting that time 
 did not have a statistically significant effect on the results. This also 
 makes sense, as both assisted and unassisted trials took roughly the same 
 amount of time to complete.

There are many ways this system could be improved. I believe the main issue 
was that the LLM outputted coordinates for the robot to move to. While the 
LLM is good at reasoning, it sometimes struggles to convert that reasoning 
into precise coordinates and perform path planning.

To improve this, I would change the system so the LLM provides high-level 
plans instead of raw coordinates. These plans would call predefined functions. 
We would then implement the code inside these functions to handle the parts the 
LLM struggled with, such as choosing safe paths and calculating the correct 
coordinates for the robot to move to.

By separating the high-level reasoning (LLM) from the low-level motion planning 
(code), the robot would likely perform tasks more reliably and consistently.
